# Customer Churn Prediction

Навчальний проєкт з бінарної класифікації: за характеристиками клієнта телекомунікаційної компанії дослідити можливість прогнозувати відтік. Цільова змінна `Churn`: `Yes` — клієнт пішов, `No` — залишився. Поточний етап охоплює лише структуру проєкту та первинний аналіз; модель ще не навчалась.

## Дані

Використовується IBM Telco Customer Churn: характеристики клієнтів, послуг, контрактів та платежів. Важливі поля: `customerID` (ідентифікатор, не ознака моделі), `gender`, `SeniorCitizen`, `tenure`, `Contract`, `InternetService`, `TechSupport`, `PaymentMethod`, `MonthlyCharges`, `TotalCharges` і `Churn`. Датасет також містить інші ознаки послуг.

Оригінальний CSV з [прикладу IBM](https://github.com/IBM/telco-customer-churn-on-icp4d) розміщується локально як `data/raw/WA_Fn-UseC_-Telco-Customer-Churn.csv`. Якщо файла немає, завантажте його з [IBM](https://raw.githubusercontent.com/IBM/telco-customer-churn-on-icp4d/master/data/Telco-Customer-Churn.csv) і збережіть під цим ім'ям, або завантажте CSV з [Kaggle](https://www.kaggle.com/datasets/blastchar/telco-customer-churn). Перевіряйте умови використання джерела. Сирі дані не змінюються ноутбуком і не включаються до Git.

## Середовище та запуск

Потрібні Python 3.11 або новіший і Git. Для найпростіших установок рекомендовано Python 3.11–3.13; доступність пакетів залежить від версії Python та платформи. У PowerShell з кореня проєкту:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m jupyter lab
```

Замініть `-3.13` на встановлену підтримувану версію, наприклад `-3.11`. У Jupyter відкрийте `notebooks/01_dataset_analysis.ipynb`, виберіть ядро середовища `.venv` і виконайте комірки послідовно. У VS Code також виберіть це середовище як ядро ноутбука. Ноутбук шукає CSV при запуску як із кореня проєкту, так і з каталогу `notebooks`.

## Структура

```text
data/raw/          незмінений вхідний CSV
data/processed/    підготовлені дані майбутніх експериментів
notebooks/         дослідження та майбутні експерименти
src/               майбутній повторно використовуваний код
models/            майбутні збережені моделі
reports/figures/   згенеровані графіки
reports/research/  матеріали дослідження
```

Ноутбуки підготовки даних, навчання й оцінювання та модулі `src` будуть створені на відповідних наступних етапах.

## План експериментів

1. Дослідити розміри, типи, пропуски, дублікати, розподіл класів та ознак; окремо перевірити порожні й нечислові `TotalCharges`.
2. Перед вибором ознак та налаштуванням моделі відокремити стратифіковану тестову вибірку й не використовувати її для прийняття рішень. Початковий аналіз у ноутбуку є описовим і не є фінальною оцінкою моделі.
3. На навчальних даних побудувати відтворюваний pipeline: обробка пропусків, кодування категорій та масштабування за потреби; усі перетворення навчати тільки на відповідній навчальній частині, зокрема всередині крос-валідації.
4. Порівняти наївний baseline з логістичною регресією та іншими моделями, використовуючи стратифіковану крос-валідацію. Врахувати дисбаланс класів і зафіксувати random seed.
5. Після вибору моделі й порога один раз оцінити її на тестовій вибірці: precision, recall, F1, ROC-AUC, PR-AUC та матриця помилок. Вибір основної метрики і порога залежить від вартості помилок для бізнесу.
6. За потреби дослідити XGBoost, CatBoost і SHAP на пізнішому етапі; зараз ці залежності не встановлюються.

Оскільки дані є історичним зрізом, перед практичним використанням потрібно визначити момент і горизонт прогнозу та переконатися, що всі ознаки доступні на момент прогнозування.
